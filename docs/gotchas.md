# Gotchas

Things that cost time while building hyprdeb on Debian 13 with Hyprland 0.55. Each item was seen on real hardware or in a
virtual machine; versions are the ones that were installed (Hyprland 0.55.2, Quickshell 0.3.0, Qt 6.8.2, mako 1.10.0, kitty
0.41.1, NVIDIA 550).

## Hyprland 0.55 (Lua)

- Hyprland 0.55 reads **`~/.config/hypr/hyprland.lua`**. Debian ships the default at `/usr/share/hypr/hyprland.lua` (type stubs in
  `/usr/share/hypr/stubs/`). A leftover `~/.config/hypr/hyprland.conf` makes Hyprland show the red "autogenerated config"
  banner; moving it away fixes that (the installer renames it to `.disabled`).
- Autostart: `hl.on("hyprland.start", function () hl.exec_cmd("waybar") end)`. `hl.exec_cmd` runs the program through
  `/bin/sh -c`, so its parent is a shell, not Hyprland.
- Dispatching from a shell: `hyprctl dispatch 'hl.dsp.exec_cmd("waybar")'`. The old `hyprctl dispatch exec waybar` is an error.
  DPMS uses the Lua dispatcher too (the old `dispatch dpms off` no longer works).
- Over SSH `hyprctl` needs `XDG_RUNTIME_DIR=/run/user/$(id -u)` and
  `HYPRLAND_INSTANCE_SIGNATURE=$(ls -t $XDG_RUNTIME_DIR/hypr | head -1)`; `hyprctl -i 0 ...` finds the first instance without it.
- Several `hl.config({ input = { ... } })` blocks merge **per key**, so a later block changes only the keys it names. hyprdeb
  relies on this: the generated `hyprdeb-settings.lua` writes only the settings that exist in `settings.toml`.
- A bind with `description = "Group: text"` shows up in `hyprctl binds -j`; hyprdeb's shortcut list is built from that.
  `SUPER + slash` fires with any keyboard layout; some other key codes report an empty key name.
- `hyprctl switchxkblayout all 0` switches every keyboard to the first layout (hyprdeb uses it before locking and before
  a password dialog).

## Sessions: `start-hyprland` and `graphical-session.target`

`start-hyprland` from a text console does **not** activate `graphical-session.target`. Packages that ship systemd *user* units
wanted by that target (hypridle, hyprpaper, hyprpolkitagent) therefore do not start by themselves, and the installer starts them
with `hl.exec_cmd`. Use one mechanism or the other, never both, or you get two daemons. A `pgrep -x hypridle || hypridle` guard
does not work either: `pgrep` is not per session, so a second Hyprland on another console would skip its daemons.

Debian's `hyprpolkitagent` only has a systemd user unit; the agent binary is `/usr/libexec/hyprpolkitagent` (not on `PATH`) and is
started from the autostart block. Without a polkit agent every password dialog (pkexec, the NAS helper, system Flatpak installs)
silently has nobody to show it.

## Lock screen and keyboard layouts

A password typed with a non-Latin layout active is refused by hyprlock, and the lock screen does not show which layout is on.
hyprdeb therefore keeps the **first layout Latin** (validated against a list), `hyprdeb-lock` switches to layout 0 before locking,
and hyprlock shows the active layout. `hypridle` calls `hyprdeb-lock` for `loginctl lock-session` and before sleep;
`hyprdeb-lock` checks the real lock state and removes stray hyprlock processes first.

Polkit's password dialog has the same trap; the CLI switches to layout 0 just before it starts an action that shows one.

kitty 0.41.1 matches shortcuts on the key of the current layout, never on the US key. With a Persian layout active,
`ctrl+shift+c` arrives as `ctrl+shift+ز`, so `config/kitty/hyprdeb.conf` maps those two keys explicitly. Harmless with only US.

## NVIDIA

- Debian 13 ships driver 550. It needs `contrib` and `non-free` and does not load with Secure Boot on (no enrolled MOK).
- Wayland needs `options nvidia-drm modeset=1 fbdev=1` and, for a clean resume, `NVreg_PreserveVideoMemoryAllocations=1` with
  `NVreg_TemporaryFilePath=/var/tmp` (`/tmp` is a tmpfs on Debian 13, so VRAM copies would live in RAM).
  `nvidia-suspend`, `nvidia-resume` and `nvidia-hibernate` services must be enabled (`nvidia-suspend-common`).
  The stage runs `update-initramfs -u` and asks for a reboot; check `/proc/driver/nvidia/params`.
- `hypridle` takes a delay inhibitor so that suspend waits until the lock screen is drawn on every output. logind's delay
  limit defaults to 5 s, so the logind drop-in raises `InhibitDelayMaxSec` to 10. It takes effect at the next boot; do not
  restart `systemd-logind` from a graphical session.

## Quickshell

Hot reload followed within about 0.3 s by closing the window crashes Quickshell 0.3.0 / Qt 6.8.2 (the old window is torn
down while Qt still uses it). The windows set `Quickshell.watchFiles = false`. Consequence: a window that was open
*before* an update keeps its old QML; close and reopen it.

## mako

mako 1.10.0 crashes when it restores a notification that do-not-disturb hid and the mode is off by now. `SUPER+SHIFT+N` goes
through `hyprdeb restore`, which only restores when that is safe. mako also forgets its modes when it restarts; `hyprdeb dnd sync`
puts do-not-disturb back to what `settings.toml` says at login.

## hyprpaper

The wallpaper block is generated from `[wallpaper]`; the default image is a plain gradient made by `assets/make-wallpaper.py`
(standard library only, reproducible), created once if `~/.config/hypr/wallpaper.png` does not exist.

## Packages

- Available in Debian 13 or its backports: Hyprland and the Hypr* tools, hyprland-guiutils, quickshell, hyprlauncher, hyprsunset,
  hyprpicker and cliphist. Not available (so not used): matugen, yazi, walker, gpu-screen-recorder.
- Installing from backports with `-t trixie-backports` can upgrade shared libraries (it upgraded `curl`/`libcurl4t64`).
  `apps.list` and the other lists use stable; only `desktop.list` uses backports.
- Kate pulls about 145 KDE/Qt packages. It is in `apps.list`; remove the line if you do not want it.
- `libspa-0.2-bluetooth` must come from the same repository as PipeWire (backports), or Bluetooth audio breaks.

## Flatpak

System-wide remote (`/var/lib/flatpak`): one installation for all users; installing as a normal user asks for your password
through polkit. `xdg-desktop-portal-gtk` provides the file chooser Flatpak apps need; the Hyprland portal has none.
`config/hypr/flatpak.lua` adds the Flatpak export directories to `XDG_DATA_DIRS` for the session.

## Claude Desktop (Cowork)

`--cowork` only prepares the machine for Claude Desktop's Cowork VM (QEMU, OVMF, virtiofsd, the `kvm` group, the `vhost_vsock`
module). Group membership applies after a full re-login (starting `start-hyprland` again from the same console keeps the old
groups). Claude Desktop itself is not installed by hyprdeb; `gnome-keyring` is installed because it needs a secret store to keep
its sign-in.

## NetworkManager and DHCP client identifiers

A router that ties its lease to the DHCP client identifier hands out a different address when the client changes. ifupdown with
dhcpcd sends `ff` + the last four MAC bytes (IAID) + dhcpcd's DUID; NetworkManager's default is different. See
[recovery.md](recovery.md#networkmanager) for how the stage keeps the old identifier, and what to check on your router.

## Mounting SMB shares

Samba's `server min protocol = SMB3` means 3.1.1 only, so a mount with `vers=3.0` is refused by such a server; hyprdeb mounts with
`vers=3.0` and its Test button forces the same dialect. A lazy `umount` happens when an automount is stopped before its mount
(stopping the automount detaches the mount point), which is why the NAS helper stops the mount first and refuses to remove a
share that is busy.
